https://parlament-glosowania.vercel.app/

W Redirect URLs dodaj ten sam adres, z końcowym ukośnikiem:
https://parlament-glosowania.vercel.app/

2. SUPABASE — UTWÓRZ TABELĘ KONT

W rozpakowanej paczce otwórz folder supabase, a w nim setup.sql.
Otwórz ten plik w Notatniku lub innym edytorze tekstu i skopiuj całość.
W panelu Supabase wybierz SQL Editor → New query.
Wklej skopiowaną treść i kliknij Run. Poczekaj na komunikat powodzenia.

Skrypt tworzy tabelę parlament_accounts i reguły dostępu.
Użytkownik widzi własne konto i nie może sam nadać sobie płatnego dostępu.
Skrypt nie wymaga hasła do bazy ani wpisywania kluczy w jego treści.

3. POŁĄCZ VERCEL Z SUPABASE

W projekcie Supabase otwórz przycisk Connect i znajdź Project URL.
Klucz Publishable key znajdziesz także w Settings → API Keys.
Potrzebujesz adresu projektu i klucza zaczynającego się od sb_publishable_.
Nie wybieraj Secret key ani service_role. Niczego nie musisz wysyłać na czat.

Otwórz swój projekt Vercel:
https://vercel.com/tomasz14/parlament-glosowania
Wybierz Settings → Environment Variables.
Dodaj dwie zmienne, zaznaczając środowisko Production:

Name: SUPABASE_URL
Value: Twój Project URL, np. https://abcdef.supabase.co

Name: SUPABASE_PUBLISHABLE_KEY
Value: Twój Publishable key, zaczynający się od sb_publishable_

Zapisz obie zmienne przed wgraniem nowych plików.
Dotychczasowych ustawień modułu AI nie usuwaj.

WYSYŁANIE E-MAILI DO ZWYKŁYCH UŻYTKOWNIKÓW

Domyślna poczta Supabase jest przeznaczona do testów. Wysyła wiadomości
wyłącznie na adresy członków zespołu projektu i ma bardzo niski limit.
Logowanie do panelu Supabase przez GitHub nie usuwa tego ograniczenia.
Na pierwszy test użyj e-maila widocznego na Twoim koncie Supabase.

Aby dowolna osoba mogła dostać link, podłącz dostawcę poczty w ustawieniach
Authentication → Email / SMTP Settings. Wpisz jego host, port, login,
hasło SMTP oraz zatwierdzony adres nadawcy. Nie wklejaj tych danych do kodu.
Dostawca może wymagać własnej domeny i potwierdzenia rekordów DNS.
Instrukcja: https://supabase.com/docs/guides/auth/auth-smtp

LOGOWANIE PRZEZ GOOGLE, APPLE I INNE KONTA

Kod obsługuje Google, Apple, Facebook, Microsoft, LinkedIn, X, GitHub
i Discord. Każdego dostawcę trzeba osobno skonfigurować i włączyć w Supabase:
Authentication → Sign In / Providers.

Zazwyczaj potrzebujesz aplikacji OAuth utworzonej w panelu danego dostawcy,
jej Client ID i Client Secret. Adres callback skopiuj z ustawień tego
dostawcy w Supabase — to adres Supabase zakończony /auth/v1/callback.
Nie zastępuj go adresem strony Vercel.
Adres strony Vercel pozostaje w URL Configuration z kroku 1.

Przyciski pojawią się automatycznie po włączeniu danego dostawcy w Supabase
i odświeżeniu strony. Do tego czasu ich nie pokazujemy.
Samo zalogowanie się do panelu Supabase przez GitHub NIE uruchamia
logowania GitHub dla użytkowników Twojej strony.
Instrukcje: https://supabase.com/docs/guides/auth/social-login

KONTA FIRMOWE I PŁATNOŚCI

Osoby prywatne otrzymują bezpłatny dostęp po potwierdzeniu e-maila i wyborze
rodzaju konta. Firma może założyć konto, ale nie otrzymuje dostępu do danych
bez aktywnego płatnego planu. W tej wersji nie ma jeszcze płatności,
ustalonej ceny ani automatycznego uruchamiania abonamentu.
Strona pokazuje firmie komunikat, że oferta jest w przygotowaniu.
Nie pobiera pieniędzy. Monitoring, alerty oraz eksport CSV/PDF nie są
jeszcze wdrożone. To kolejny etap po ustaleniu oferty firmowej.

GDY COŚ NIE DZIAŁA

„Logowanie jest w przygotowaniu”: sprawdź obie zmienne w Vercel oraz Redeploy.
„Nie można odczytać danych konta”: sprawdź wynik uruchomienia setup.sql.
Brak e-maila: sprawdź spam, właściwy adres konta Supabase i konfigurację SMTP.
Brak przycisku Google/GitHub: włącz i skonfiguruj danego dostawcę w Supabase.
Powrót z logowania na localhost: popraw Site URL oraz Redirect URLs.
Stary wygląd strony: sprawdź status Ready i odśwież stronę Ctrl+Shift+R.

prawdziwego e-maila, OAuth i reguł bazy wymaga Twojego projektu Supabase
oraz wdrożenia opisanych powyżej ustawień.
